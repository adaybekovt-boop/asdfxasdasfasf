# Карта мышления

Статический мобильный тест на русском языке. Ответы сохраняются только в `localStorage` браузера, а основной итоговый разбор (12-осевая карта, шкалы, связный разбор) строится локально по сочетаниям шкал, философских выборов и структуре свободных ответов — без аккаунта, базы данных и API.

Отдельно на экране результата есть необязательная кнопка «Проверить ответы»: она отправляет ответы во внешнюю модель (DeepSeek) через серверную функцию и показывает её краткий разбор сильных/слабых сторон. Это дополнение к локальному методу, а не замена ему — статистика и шкалы от него не зависят и не меняются.

## Что внутри

- 48 утверждений по 12 шкалам;
- 8 философских дилемм;
- 5 необязательных свободных ответов;
- сохранение и продолжение на том же устройстве;
- двенадцатиосевая карта и локальный содержательный разбор;
- экспорт отчёта в текст и JSON;
- необязательный разбор от DeepSeek (1 раз в сутки на пользователя);
- адаптация под экран около 390 px, клавиатуру и `prefers-reduced-motion`.

## Запуск

Публичные файлы сайта — `index.html` и `_headers`. Серверная часть (`/api/analyze`) — Cloudflare Worker со статическими ассетами: код воркера лежит в `src/worker.js`, конфигурация — в `wrangler.jsonc`, `.assetsignore` не даёт исходникам (`src/`, `wrangler.jsonc`, `.md`-файлы, `.git`) попасть в раздаваемые статические ассеты.

Для локальной проверки основного теста достаточно отдать корень любым статическим HTTP-сервером — кнопка «Проверить ответы» при этом просто покажет ошибку сети, это ожидаемо без развёрнутого воркера. Проверить конфигурацию воркера локально: `npx wrangler deploy --dry-run` (ничего не публикует, только валидирует `wrangler.jsonc`).

## Публикация

Проект — git-connected Cloudflare Worker (Workers & Pages → этот проект → вкладки Deployments/Bindings/Settings), деплоится через Workers Builds: при пуше в ветку Cloudflare сам собирает и выкладывает `src/worker.js` вместе со статическими ассетами из `wrangler.jsonc`. Отдельно собирать или пушить руками не нужно.

### Настройка разбора от DeepSeek (один раз в панели Cloudflare)

1. **Ключ API.** В проекте (Workers & Pages → этот Worker) → Settings → Variables and Secrets добавь секретную переменную `DEEPSEEK_API_KEY` со значением своего ключа DeepSeek.
2. **Модель (опционально).** Если у DeepSeek другое точное имя модели, которое хочется использовать вместо дефолтной `deepseek-chat`, добавь обычную (не секретную) переменную `DEEPSEEK_MODEL` со значением нужного id — без изменения кода.
3. **Лимит «1 анализ в сутки».** Создай KV-неймспейс: Workers & Pages → KV → Create namespace (например `mind-map-rate-limit`). Затем в этом Worker → Bindings → Add binding → KV namespace, имя переменной `RATE_LIMIT_KV`, значение — созданный неймспейс.
4. Сохрани — переменные и биндинги подхватываются уже следующим деплоем (например, следующим пушем в ветку).

Без шага 1 кнопка «Проверить ответы» будет корректно показывать «Анализ пока не настроен на сервере» — сам тест при этом работает как обычно. Без шага 3 лимит в сутки просто не будет применяться (KV — необязателен, но без него ограничение не работает).

Если имя воркера в панели отличается от `test` (указано в `name` в `wrangler.jsonc`), поправь `name` в `wrangler.jsonc` на реальное — иначе `wrangler versions upload` может расходиться с тем, к какому воркеру привязан git-деплой.
